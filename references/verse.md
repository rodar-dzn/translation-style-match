# Embedded verse

Songs, poems, epigraphs, prophecies, inscriptions. A small fraction of the
word count and a large fraction of the risk, because verse fails visibly.

## The governing principle

Verse in prose is not translated for meaning. It is translated for
**function** — what the passage does in the scene it sits in. Establish the
function first, then decide what to sacrifice, because you will sacrifice
something.

Common functions, and what each one makes non-negotiable:

| Function | Must survive | May be sacrificed |
|---|---|---|
| Sung by a character | singability, metre, stanza count | literal imagery |
| Prophecy referenced later | the specific words later callbacks quote | metre, rhyme |
| Epigraph setting tone | register and imagery | metre |
| Comic verse | the joke landing | nearly everything else |
| Inscription / riddle | any wordplay the plot turns on | form, length |

Getting this wrong in the safe-looking direction is the usual error: a
faithful literal rendering of a song that no longer scans, in a scene where
characters are singing it.

## Method

1. **Read the surrounding prose first.** Does anyone react to the verse?
   Reactions constrain the translation — a joke that gets a laugh must be a
   joke; a line called beautiful must be beautiful.

2. **Check for later callbacks.** Grep the source for distinctive phrases
   from the verse. If a line is quoted again fifty pages on, that line is
   load-bearing and its rendering is fixed from now on. Record it in the
   glossary like any other canonical term.

3. **Profile the corpus's verse policy.** Does the reference translation
   rhyme where the source rhymes? Preserve syllable counts? Use accentual
   or syllabo-tonic metre? Mark verse with italics, indentation, or
   blockquote? Answer these from the corpus before writing a line.

4. **Draft for form, then repair meaning.** Working the other way — literal
   first, then squeezing it into metre — reliably produces padding. Write to
   the metre from the start and let the imagery adjust.

5. **Read it aloud.** In the target language. Non-negotiable, and the step
   most often skipped.

## Structural features that carry meaning

Some formal features are not decoration:

- **Anaphora and refrains.** If every stanza opens the same way, that
  parallelism usually tracks a narrative progression. Preserve the parallel
  openings even at cost to the individual lines, because the progression is
  the point.
- **Stanza count.** Where verse is interleaved with action, the stanzas are
  pacing the scene. Merging or dropping one desynchronizes it.
- **A broken final line.** Where the last stanza departs from the
  established pattern, that break is almost always the payload.

## Performance artifacts

Where a character sings while doing something else, the text may carry
stutters, breaks, interruptions, or dialect spellings. These belong to the
*performance*, not the song. Preserve them in the same positions relative to
the metre — moving a stutter to a more convenient syllable loses the
information that the singer faltered at a particular moment.

Do not silently normalize them away. If a break cannot be placed naturally,
say so in the review rather than deleting it.

## Reviewing verse

Check, in this order:

- [ ] Does it scan when read aloud?
- [ ] Does the rhyme scheme match the corpus's policy, not just the source's?
- [ ] Stanza count preserved?
- [ ] Parallel openings and refrains preserved?
- [ ] Do the prose reactions around it still make sense?
- [ ] Are later callbacks consistent with this rendering?
- [ ] Performance artifacts in their original metrical positions?
- [ ] Formatting matches the corpus (italics? indent? blockquote?)

A failure on the first or fifth item outranks any inaccuracy of imagery.
